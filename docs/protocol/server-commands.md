### Бросок гранаты

При успешном использовании сервер может подтвердить слот через `se`, а после `ud` отправить `uw`, обновление веса `0v`, `ef|1` и `fb`. `uw` задаёт таймер ожидания оружия.

```text
C→S ue|0
S→C se|0
C→S ud|15945|-7025|2|-1|-1|-1|-1
S→C uw|2000
S→C ef|1
S→C fb|0|357|56|944|60|938|56|942|0|0|589|2|1
```

В `fb` тип `0` выбирает спрайт гранаты и взрыв, тип `1` — фейерверк (`NuclearWorld.GRENADE_PARAMS`). Клиент рисует дугу по параметрам сервера, затем включает анимацию и звук в клетке `hitI, hitJ` (`EffectObject.endFly`). Отдельного пакета для запуска этой анимации в тесте не было. Урон сервер сообщает через `ht` для каждой поражённой цели, а смерть — через `dd`. В `fb` нет ID бросившего, а в `ht` нет ссылки на конкретный бросок.

### Ход атаки

C→S `at|sessionId` задаёт цель и начинает атаку. До первого выстрела сервер может прислать `mv` для сближения. S→C `at` сообщает о выполненной атаке и содержит клетку цели. Чтобы связать выстрел со своим персонажем, нужно сопоставить эту клетку со своей позицией на момент атаки. Точный момент, когда другое существо выбрало цель, из S→C `at` неизвестен.

Сообщения `ht` и `0e` содержат ID существа, к которому относится результат, но не ID атакующего. Поэтому по ним одним нельзя связать результат с конкретным выстрелом.

Здесь `opId` — номер операции, который сервер увеличивает при каждом изменении сделки; клиент запоминает последний (`barterOpId`) и отправляет его в `ac`.

| Команда | Формат | Действие клиента |
|---|---|---|
| `ar` | `ar\|userId\|name\|action` | вам предлагают действие → окно с таймером 10 с (`aa`/`al`) |
| `aw` | `aw\|userId\|name\|action` | ожидание ответа собеседника |
| `al` | `al` | закрыть текущее окно действия. Для мирового бартера приходит после завершения безопасного таймера вместе с финальными обновлениями состояния; поэтому сам по себе `al` не доказывает ни успех, ни отмену сделки |
| `am` | `am\|action\|…` | открыть окно сделки: 1 — бартер, 3 — просьба о ремонте, 4 — ремонт, 5 — просьба о лечении, 6 — лечение. Для ремонта и лечения данные начинаются с индекса 8 |
| `bb` | `bb\|action\|-\|tradeSkill\|npcTradeSkill\|npcSessionId\|title\|N\|{item}×N\|{item}…\|` | торговля у NPC (`action` = 1). Первые N предметов — вещи игрока (правая колонка `BotBarter` под его именем), остальные до конца — товары NPC (левая колонка с заголовком `title`). Цена покупки — `price × getNumber7(tradeSkill − npcTradeSkill)`, множитель от 1.1 до 2.2. При `action` 3 и 5 (ремонт и лечение) открывается `BarterMenu` с данными с индекса 7 |

| `od` | `od\|opId` | новый номер операции |
| `to` | `to\|opId\|traum` | травма вылечена |
| `hf` | `hf` | лечение не удалось |
| `rp` | `rp\|inventoryId\|value` | предмет в инвентаре отремонтирован |

| `iv` | `iv\|-\|{item}…\|` | открыть инвентарь (поле 1 клиент не читает) |
| `rk` | `rk\|workbenchId\|N\|{recipe}×N` | рецепты крафта (`CraftSystem.parseCraftRecipes`), см. ниже. Повторный ответ для того же `workbenchId` игнорируется |
| `rv` | `rv\|workbenchId\|N\|{recipe}×N` | рецепты улучшений (`CraftSystem.parseUpgradeRecipes`), см. ниже |
| `ug` | `ug\|N\|{upgradeCategory\|M\|upgrade×M}×N` | какие улучшения применимы к категории предмета (поле 11 `{item}`). Улучшения нумеруются `CraftSystem.*` (0–25), название — `IDS_UPGRADE_<n>` |
| `ld` | `ld\|…` | журнал ячейки (`ui/menus/DepodLogMenu.as`) |

Рецепты `rk` и `rv` (`workbenchId` — номер верстака из `02`, типы 24 и 25):

```
rk: id|productCount|group|skillType|skillValue|K|{instrumentId|name}×K|<item>|M|{id|name|count}×M
rv: id|upgrade|skillType|skillValue|K|{instrumentId|name}×K|M|{id|name|count}×M
```

`skillType` = −1 — навык не нужен; иначе нужен навык `skillType` не ниже `skillValue`. Инструменты выводятся одной строкой через `/`.
Ингредиенты с отрицательным id — не предметы. Так, `-3` — рубли: в окне улучшения их количество умножается на `1 + уровень предмета`. Номера от −269 до −292 — наборы улучшений (`WT …` для оружия, `AT …` для брони).
`rv` хранится по номеру улучшения `upgrade`, а `id` (например, `100000000 + n`) отправляется в запросе улучшения.
Полное описание механики — окно, шанс, цены и правила сервера — в [upgrade.md](upgrade.md).

## Чат

| Команда | Формат | Действие клиента |
|---|---|---|
| `sg` | `sg\|channel\|sender\|text…` | сообщение в чат, см. ниже |
| `po` | `po\|userId\|name` | открыть приватный канал |
| `cl` | `cl\|{короткая запись}…\|` | добавить пользователей в список чата |
| `cu` | `cu\|<короткая запись>` | добавить или обновить одного |
| `cd` | `cd\|{sessionId\|}…` | удалить из списка чата |
| `dc` | `dc` | очистить списки чата |

Каналы `sg` (`ChatPanel.doAction307`, системные сообщения — `ChatPanel.formatSystemMessage`):

| channel | Значение |
|---|---|
| < 0 | приват; канал создаётся при необходимости |
| 0, 2, 3 | общий, торговый, клановый: `text` — текст сообщения |
| 1 | события: `text` = `msgId\|args…`, выводится `IDS_SYS_MSG_<msgId>`. Для `msgId = 27` аргументы — `N\|{name\|count}×N` |
| 5 | событие (в канал событий), формат как у 1 |
| 6 | системное сообщение; `sender == "1"` меняет цвет |
| 7 | системное сообщение в активный канал |
| 9 | журнал клана (или общий канал, если клана нет) |
