# Улучшение предметов

Обозначения — в [overview.md](overview.md#как-читать-документы).
Запись предмета с полем `upgrades` — в [data-structures.md](data-structures.md#запись-предмета-inventoryitem), окно `02` — в [numeric-commands.md](numeric-commands.md#типы-окон-для-02).

Улучшение — отдельная механика поверх инвентаря: у предмета есть категория (`upgradeCategory`) и список установленных улучшений (`upgrades`), а сервер выдаёт две таблицы — какие улучшения применимы к категории (`ug`) и что они стоят (`rv`). Установка идёт командой `iu`, снятие — `iw`.

Где в коде: `ui/menus/UpgradeMenu.as` (окно), `game/CraftSystem.as` (таблицы и формула шанса), `game/InventoryItem.as` (поля записи), `ui/ItemInfo.as` (подсказка предмета), `net/GameSocket.as` (`iu`, `iw`, `rv`, `ug`).

## Как открывается окно

```
C→S  us|objectId                     использовать объект-верстак
S→C  ue||objectId|                   анимация объекта ([ue, ut, oe](#ue-ut-oe))
S→C  oe|1000                         таймер своего действия, мс
S→C  ut|sessionId|i|j|targetI|targetJ   персонаж поворачивается и «работает»
S→C  02|25|canRemoveUpgrades|N|{item}×N|workbenchId      окно улучшения
```

Окно приходит только в ответ на `us`, с задержкой порядка `oe`. Повторный `us` по тому же объекту присылает `02|25` заново — так окно обновляется.

**Формат `02|25`** (`UpgradeMenu.parseData`):

```
02|25|canRemoveUpgrades|N|{запись предмета}×N|workbenchId
```

| Поле | Смысл |
|---|---|
| `canRemoveUpgrades` | `1` — кнопка «Снять улучшения» доступна (команда `iw`) |
| `N`, `{item}×N` | предметы игрока, у которых `upgradeCategory != 0`; запись — обычная, с префиксом длины |
| `workbenchId` | номер верстака, ключ кэша `rv`; например, `0` |

Пример (сокращённо):

```
02|25|0|9|39|88|4013599|0|0|Glock 18|7|10028|0|970|625|2|0|0|0|0|700|0|0|99|0|2|12|18|90|…
```

Здесь `canRemoveUpgrades = 0`, `N = 9`, первый предмет — `39` полей, `itemId 88`, `inventoryId 4013599`, «Glock 18», уровень 7, `upgradeCategory 2`, установленных улучшений 0.

Список не зависит от того, надет предмет или лежит в сумке, и не включает расходники и наборы улучшений (`upgradeCategory = 0`).

Окно закрывается только на клиенте: кнопка «Закрыть» вызывает `closeMenu` и пакет не отправляет. Сервер узнаёт о закрытии косвенно — по `iv` он присылает `dl` (и `al`, если были открыты окна действий), после чего уже идёт сам `iv`.

### `ue`, `ut`, `oe`

Это только анимация и таймер, состояние они не меняют, но в сценарии использования верстака участвуют все три:

- `ue|-|objectId|` — объект проигрывает анимацию использования (`World.useObject` → `ObjectItem.useObject`, качание для дверей, ящиков, диалоговых объектов, ячеек склада, фабрик);
- `ut|sessionId|i|j|targetI|targetJ` — существо встаёт в `(i, j)`, разворачивается на `(targetI, targetJ)` и играет анимацию действия (`World.playerUseTarget`);
- `oe|ms` — таймер своего действия, клиент рисует по нему полоску (`UpPanel.startUseWait`). Не путать с `uw|ms` — таймер перезарядки оружия.

## Таблица групп `ug`

```
ug|N|{upgradeCategory|M|upgrade×M}×N
```

Ответ на C→S `ug`. Клиент запрашивает его один раз за сессию — при первом открытии окна, пока `CraftSystem.UpgradeGroupsLoaded == false`. Каждый новый ответ целиком заменяет таблицу (`CraftSystem.parseUpgradeGroups`).

Пример:

| cat | upgrade | Что за категория |
|---|---|---|
| 1 | 0,1,3,4,5,15,16,18,19,20 | оружие без магазина (нож, бита) |
| 2 | 0,1,2,3,4,5,15,16,**17**,18,19,20 | оружие с магазином |
| 3 | 2,5,17,20 | только «магазин» и «прочность» |
| 4 | 6,7,8,9,10,**11**,21,22,23,24,25 | шлем (+Восприятие) |
| 5 | 6,7,8,9,10,**12**,21,22,23,24,25 | броня (+Сила) |
| 6 | 6,7,8,9,10,**13**,21,22,23,24,25 | штаны (+Выносливость) |
| 7 | 6,7,8,9,10,**14**,21,22,23,24,25 | ботинки (+Ловкость) |

Категория приходит в самом предмете (поле `upgradeCategory`), клиент не выводит её из типа: «Glock 18» — категория 2, «+ALPHA нож» и «Бита» — 1.

## Таблица рецептов `rv`

```
rv|workbenchId|N|{recipe}×N
recipe: id|upgrade|skillType|skillValue|K|{instrumentId|name}×K|M|{id|name|count}×M
```

Ответ на C→S `rv`. Кэшируется по `workbenchId`, повторный ответ для того же верстака игнорируется (`CraftSystem.parseUpgradeRecipes`).

- `id` — то, что клиент отправляет в `iu`. **Это не номер улучшения:** `id = 100000000 + порядковый номер строки в списке`, поэтому, например, `100000013` соответствует улучшению 11, а `100000025` — улучшению 20.
- `skillType` = −1 — навык не требуется; иначе нужен навык `skillType` не ниже `skillValue`.
- `K` — инструменты.
- `M` — ингредиенты. Отрицательный `id` — не предмет: `-3` рубли, `-269…-292` наборы улучшений (тип предмета 12).

Название — `IDS_UPGRADE_<n>`. Числовые эффекты видны только в подсказке предмета: `ItemInfo.create` дорисовывает их к базовым параметрам из записи.

| upgrade | Эффект | upgrade | Эффект |
|---|---|---|---|
| 0 | точность +10 % | 15 | точность +15 % |
| 1 | пробитие брони +10 % | 16 | пробитие +15 % |
| 2 | магазин +10 % | 17 | магазин +15 % |
| 3 | урон +5 % | 18 | урон +8 % |
| 4 | требуемая сила −1 | 19 | требуемая сила −1 |
| 5 | шанс поломки −20 % | 20 | шанс поломки −30 % |
| 6 | класс брони +7 % | 21 | класс брони +10 % |
| 7 | сопр. нормальному +15 | 22 | сопр. нормальному +25 |
| 8 | сопр. плазме +15 | 23 | сопр. плазме +25 |

## Окно `UpgradeMenu`

Слева слот с предметом и стрелки ‹ ›, справа список доступных улучшений, ниже — ингредиенты выбранного, шанс, кнопки «Снять улучшения», «Улучшить», «Закрыть».

**Список улучшений** (`UpgradeMenu.updateCurrentItem`): берётся `CraftSystem.UpgradeGroups[item.upgradeCategory]`, из него выбрасываются улучшения, которые уже стоят (`InventoryItem.hasUpgrade`), и те, для которых нет рецепта.

**Шанс** — только надпись, бросок делает сервер:

```
шанс = int((25 + 75 / e^N) · (1 + навык_ремонта / 500)),  показывается min(шанс, 100)
```

`N` — сколько улучшений уже установлено, `навык_ремонта` = `skills[SKILL_REPAIR] / 10000` (`Character.SKILL_REPAIR = 6`). При навыке 10: N=0 → 100 %, N=1 → 53 %, N=2 → 35 %, N=3 → 29 %, N=4 → 26 %, N=5 → 26 %, N≥6 → 25 %. При навыке 0: 100, 52, 35, 28, 26, 25 %. Первое улучшение любого предмета проходит гарантированно.

**Ингредиенты** (`UpgradeMenu.upgradeClick`): для каждого ингредиента выводится `name` и количество; для рублей (`id == -3`) количество умножается на `1 + уровень предмета`. Инструменты выводятся одной строкой через `/`, требование навыка — строкой «навык: текущий/требуемый».

**Кнопка «Улучшить»** (`UpgradeMenu.upgradeClickHandler`): проверяет только навык (`skills[skillType] / 10000 >= skillValue`), затем отправляет `iu|inventoryId|recipe.id` и блокируется до следующего `02|25`. Наличие ингредиентов не проверяется — `get hasRequiredIngredients` всегда возвращает `true`, поэтому игрок узнаёт о нехватке только по отказу сервера.

**Кнопка «Снять улучшения»** (`UpgradeMenu.onRemoveUpgradesClick`): доступна при `canRemoveUpgrades == 1` и непустом `item.upgrades`; после подтверждения уходит `iw|inventoryId`.

## Команды установки и снятия

| Команда | Формат | Что делает |
|---|---|---|
| `iu` | `iu\|inventoryId\|recipeId` | установить улучшение |
| `iw` | `iw\|inventoryId` | снять все улучшения с предмета |

Ни у `iu`, ни у `iw` нет ни идентификатора окна, ни токена: всё, что отправляет клиент, — два (или один) номера.

**Ответ на успешный `iu`** (пример порядка):

| Пакет | Смысл |
|---|---|
| `ic` | закрыть инвентарь и подтверждения |
| `sg\|1\|\|25\|<набор>\|1` | событие `IDS_SYS_MSG_25`: израсходован набор |
| `sg\|1\|\|25\|Рубль\|<сумма>` | то же: списаны рубли |
| `0v\|1\|21\|<вес>` | новый вес груза (`0v`, параметр 21, граммы) |
| `cv\|…` | обновление внешности — только если улучшен надетый предмет |
| `02\|25\|…` | обновлённый список предметов (разблокирует кнопку) |
| `04\|2` | уведомление `IDS_NOTIFICATION_2` |

**Ответ на отказ:** только `04|4` (`IDS_NOTIFICATION_4`), ничего не списывается и не меняется.

## Правила сервера

Рекомендуемые проверки и действия сервера. Условия 2–5 следуют из ограничений интерфейса и таблиц `ug`/`rv`; серверная обработка всех отказов не подтверждена.

1. **Окно открыто.** `02|25` отправлен этому игроку и ещё не закрыт. Из самой команды это не восстановить, а клиент о закрытии не сообщает: кнопка «Закрыть» ничего не отправляет, так что инвалидировать состояние приходится по другим командам (`iv`, повторный `us`, `dl` из других окон, выход из мира, смена зоны).
2. **Рецепт существует** для верстака, к которому относится окно.
3. **Улучшение применимо к категории:** `recipe.upgrade ∈ groups[item.upgradeCategory]`.
4. **Улучшения ещё нет:** `recipe.upgrade ∉ item.upgrades`.
5. **Навык достаточен:** при `skillType != -1` — `skills[skillType] >= skillValue`.
6. **Ингредиенты есть** в нужном количестве: набор `count` и рубли `count · (1 + item.level)`. Списание атомарно с установкой: при отказе не тратится ничего.
7. **Бросок — серверный.** `25 + 75/e^N` (N — число улучшений до установки), с модификатором навыка ремонта по формуле клиента; результат пишется в лог вместе с `inventoryId`, `recipeId` и `N`, иначе спорные случаи недоказуемы.
8. **После установки** — пересчитать параметры предмета, вес, отправить `0v`, `02|25`, `04|2`; для надетого предмета ещё `cv`.

Для `iw` необходимо очистить `item.upgrades`; возвращаются ли наборы и рубли, неизвестно.

## Открытые вопросы

- Точный текст сообщений `04|4` и `IDS_SYS_MSG_25` зависит от локализации.
- Поведение при установке улучшения на предмет с имеющимися улучшениями требует уточнения.
- Неизвестно, какие параметры оружия сервер пересчитывает после установки улучшения.
- Для `iw` неизвестны правила возврата наборов и денег и пересчёта параметров.
- Неизвестно, обязателен ли открытый интерфейс улучшения для обработки `iu`.
