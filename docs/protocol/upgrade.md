# Улучшение предметов

Обозначения — в [overview.md](overview.md#как-читать-документы).
См. [запись предмета](data-structures.md#запись-предмета) и [типы окон для `02`](numeric-commands.md#типы-окон-для-02).

Улучшение — отдельная механика поверх инвентаря: у предмета есть категория (`upgradeCategory`) и список установленных улучшений (`upgrades`), а сервер выдаёт две таблицы — какие улучшения применимы к категории (`ug`) и что они стоят (`rv`). Установка идёт командой `iu`, снятие — `iw`.

## Как открывается окно

```
C→S  us|objectId                     использовать объект-верстак
S→C  ue||objectId|                   анимация объекта
S→C  oe|1000                         таймер своего действия, мс
S→C  ut|sessionId|i|j|targetI|targetJ   персонаж поворачивается и «работает»
S→C  02|25|canRemoveUpgrades|N|{item}×N|workbenchId      окно улучшения
```

Сервер открывает окно в ответ на `us`. Задержка сопоставима со значением `oe`, например около 1,1 с. При повторном `us` по тому же объекту сервер заново отправляет `02|25`, чтобы обновить окно.

**Формат `02|25`**

```
02|25|canRemoveUpgrades|N|{запись предмета}×N|workbenchId
```

| Поле | Смысл |
|---|---|
| `canRemoveUpgrades` | `1` — кнопка «Снять улучшения» доступна (команда `iw`) |
| `N`, `{item}×N` | предметы игрока, у которых `upgradeCategory != 0`; запись — обычная, с префиксом длины |
| `workbenchId` | номер верстака, по которому клиент кэширует `rv` |

Пример (сокращённо):

```
02|25|0|9|39|88|4013599|0|0|Glock 18|7|10028|0|970|625|2|0|0|0|0|700|0|0|99|0|2|12|18|90|…
```

Здесь `canRemoveUpgrades = 0`, `N = 9`, первый предмет — `39` полей, `itemId 88`, `inventoryId 4013599`, «Glock 18», уровень 7, `upgradeCategory 2`, установленных улучшений 0.

Список не зависит от того, надет предмет или лежит в сумке, и не включает расходники и наборы улучшений (`upgradeCategory = 0`).

Кнопка «Закрыть» скрывает окно без отправки сообщения. Когда клиент запрашивает инвентарь через `iv`, сервер сначала отправляет `dl` и, если были открыты окна действий, `al`, а затем возвращает содержимое инвентаря в `iv`.

### `ue`, `ut`, `oe`

- `ue|-|objectId|` запускает анимацию использования объекта. Двери, ящики, диалоговые объекты, ячейки склада и фабрики при этом качаются.
- `ut|sessionId|i|j|targetI|targetJ` ставит существо в клетку `(i, j)`, разворачивает к `(targetI, targetJ)` и запускает анимацию действия.
- `oe|ms` задаёт длительность полосы ожидания действия своего персонажа. Для ожидания оружия используется `uw|ms`.

## Таблица групп `ug`

```
ug|N|{upgradeCategory|M|upgrade×M}×N
```

Клиент запрашивает группы командой `ug` при первом открытии окна за сессию. Каждый полученный ответ `ug` целиком заменяет таблицу.

| cat | upgrade | Что за категория |
|---|---|---|
| 1 | 0,1,3,4,5,15,16,18,19,20 | оружие без магазина (нож, бита) |
| 2 | 0,1,2,3,4,5,15,16,**17**,18,19,20 | оружие с магазином |
| 3 | 2,5,17,20 | улучшения магазина и прочности |
| 4 | 6,7,8,9,10,**11**,21,22,23,24,25 | шлем (+Восприятие) |
| 5 | 6,7,8,9,10,**12**,21,22,23,24,25 | броня (+Сила) |
| 6 | 6,7,8,9,10,**13**,21,22,23,24,25 | штаны (+Выносливость) |
| 7 | 6,7,8,9,10,**14**,21,22,23,24,25 | ботинки (+Ловкость) |

Категория приходит в самом предмете (поле `upgradeCategory`), клиент не выводит её из типа: «Glock 18» — категория 2, «+ALPHA нож» и «Бита» — 1.

## Таблица рецептов `rv`

```
rv|workbenchId|N|{recipe}×N
recipe: id|upgrade|skillType|skillValue|K|{instrumentId|name}×K|M|{id|name|count}×M
```

Клиент запрашивает таблицу командой `rv` и сохраняет её по `workbenchId`. Повторный ответ для того же верстака клиент пропускает.

- `id` — идентификатор рецепта, который клиент отправляет в `iu`. В примере ниже он равен `100000000` плюс индекс рецепта в ответе `rv`, считая с нуля. Например, `100000013` соответствует улучшению 11, а `100000025` — улучшению 20.
- `skillType` = −1 — навык не требуется; иначе нужен навык `skillType` не ниже `skillValue`.
- `K` — количество инструментов в рецепте.
- `M` — ингредиенты. Отрицательный `id` — не предмет: `-3` рубли, `-269…-292` наборы улучшений (тип предмета 12).

## Окно улучшений

Слева слот с предметом и стрелки ‹ ›, справа список доступных улучшений, ниже — ингредиенты выбранного, шанс, кнопки «Снять улучшения», «Улучшить», «Закрыть».

**Список улучшений.** Клиент показывает улучшения для категории `upgradeCategory`, которые ещё не установлены и для которых есть рецепт.

**Шанс.** Клиент рассчитывает процент для отображения, а результат определяет сервер.

```
шанс = int((25 + 75 / e^N) · (1 + навык_ремонта / 500)),  показывается min(шанс, 100)
```

`N` — число установленных улучшений. Навык ремонта берётся из поля `skill6` в записи персонажа и делится на 10 000. При навыке 10 клиент показывает 100 % без установленных улучшений, 53 % с одним, 35 % с двумя и 29 % с тремя.

**Ингредиенты.** Клиент показывает название и количество каждого ингредиента. Для рублей (`id = -3`) количество умножается на `1 + уровень предмета`. Требуемые инструменты выводятся через `/`, а навык — в виде «текущий/требуемый».

**Кнопка «Улучшить».** Если рецепт требует навык, клиент делит значение указанного навыка на 10 000 и сравнивает с `skillValue`. При достаточном навыке он отправляет `iu|inventoryId|recipeId` и блокирует кнопку до следующего `02|25`. О нехватке ингредиентов игрок узнаёт из ответа сервера.

**Кнопка «Снять улучшения».** Доступна при `canRemoveUpgrades = 1`, если на предмете есть улучшения. После подтверждения клиент отправляет `iw|inventoryId`.

## Команды установки и снятия

| Команда | Формат | Что делает |
|---|---|---|
| `iu` | `iu\|inventoryId\|recipeId` | установить улучшение |
| `iw` | `iw\|inventoryId` | снять все улучшения с предмета |

**Пример порядка пакетов после успешного `iu`**

| Пакет | Смысл |
|---|---|
| `ic` | закрыть инвентарь и подтверждения |
| `sg\|1\|\|25\|<набор>\|1` | сообщение о расходе набора |
| `sg\|1\|\|25\|Рубль\|<сумма>` | сообщение о списании рублей |
| `0v\|1\|21\|<вес>` | новый вес груза (`0v`, параметр 21, граммы) |
| `cv\|…` | обновление внешности — только если улучшен надетый предмет |
| `02\|25\|…` | обновлённый список предметов (разблокирует кнопку) |
| `04\|2` | уведомление об успешной установке |

При отказе сервер отправляет `04|4`. Инвентарь, баланс и вес остаются прежними.

В таком обмене `ic` может прийти через 100 мс после запроса, а весь ответ — занять около 240 мс.

## Пример установки улучшений

Персонаж 6-го уровня с навыком ремонта 10 и балансом 201 068 рублей открывает верстак командой `us|154141`.

| # | `iu` | Что требовалось | Ответ |
|---|---|---|---|
| 1 | `4013599/100000000` — WT Accuracy I | набор `-269` + 1600 ₽ | `04\|4` |
| 2 | `4013599/100000005` — WT Durab I | набор `-274` + 1200 ₽ | **`04\|2`** |
| 3 | `4015493/100000009` — AT ArmDurab I | набор `-284` + 1800 ₽ | `04\|4` |
| 4 | `4015493/100000009` — то же | то же | `04\|4` |
| 5 | `4015493/100000006` — AT ArmorClass I | набор `-281` + 2100 ₽ | **`04\|2`** |

Попытки 1, 3, 4 — не хватало набора (в инвентаре были только `-274` и `-281`); шанс при этом был 100 %, потому что улучшений на предметах ещё не было.

Состояние инвентаря (`iv`) до и после попыток.

```
До попыток  29 предметов, вес 37 905 г, рублей 201 068
После № 2   28 предметов, вес 36 405 г, рублей 199 868   −WT Durab I, −1200 ₽, +upgrade 5
После № 4   28 предметов, вес 36 405 г, рублей 199 868
После № 5   27 предметов, вес 34 905 г, рублей 197 768   −AT ArmorClass I, −2100 ₽, +upgrade 6
```

Стоимость зависит от уровня предмета. Для Glock 18 уровня 7 она составляет `150 · (1 + 7) = 1200` рублей, для брони уровня 6 — `300 · (1 + 6) = 2100` рублей. Вес уменьшается на 1500 г за каждый использованный набор. Рубли весят 0 г.

Сама запись предмета:

```
Glock 18    длина 39 → 40, upgrades [] → [5], параметры не изменились
Альфа броня длина 32 → 33, upgrades [] → [6], params[2] (класс брони) 62 → 66
```

Сервер прибавил к классу брони 7 % и отбросил дробную часть, поэтому значение выросло с 62 до 66. Базовые параметры оружия после повышения прочности сохранились, а клиент показал «−20 % к шансу поломки» по значению в `upgrades`.

## Открытые вопросы

1. **Шанс при `N > 0`.** Формула клиента снижает базовый шанс с каждым установленным улучшением. Применяет ли сервер ту же формулу, неизвестно.
2. **Параметры оружия.** Неизвестно, меняет ли сервер поля `params` при улучшении точности, урона, магазина или пробития.
3. **`iw` (снятие улучшений).** Неизвестно, как сервер пересчитывает `params` и возвращает ли наборы и рубли.
4. **Категория 3** (`2,5,17,20`). Какие предметы относятся к этой категории, неизвестно.
5. **Обязательность окна.** Ответ сервера на `iu` с действительным `recipeId` без открытого окна `02|25` неизвестен.
