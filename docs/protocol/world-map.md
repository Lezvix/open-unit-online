Обозначения — в [overview.md](overview.md#как-читать-документы).
Сводная таблица команд `sb`, `ub`, `ol`, `do` и др. — в [server-commands.md](server-commands.md#мир-карта-и-объекты).

## Этажи

Многоуровневые локации не разбиты на отдельные карты. Все этажи лежат в одной сетке `i`, `j`, а этаж задаёт поле `mapLevel` (0 — земля). В дампе у объектов основного мира встречаются уровни 0–4, у существ — 0, 1 и 3.

**Где передаётся этаж**

| Сообщение | Поле | Примечание |
|---|---|---|
| `ol` | `mapLevel` (поле 3 записи объекта) | у каждого объекта карты |
| `ul`, `uu` | `mapLevel` после `i`, `j` ([записи игроков](data-structures.md#записи-игроков)) | только в полных записях существ |
| `fb` | `mapLevel`, `blowLevel` | этаж броска и этаж взрыва: граната может лететь между этажами |
| `lp`, `hn` | `level` | этаж цели квеста |

В `mv`, `md` и `ms` этажа нет. Обычная ходьба всегда идёт в пределах одного этажа, клиент оставляет текущий `mapLevel` существа.

**Переход между этажами**

Отдельной команды нет. Лестница — объект `ol` с `type = 3` (`otStair` в старой версии, `ObjectItem.OBJECT_ITEM_CONST11` в восстановленном коде). Игрок использует её как обычный объект, а сервер переставляет персонажа в другую клетку с другим `mapLevel`. Подъём из дампа:

```
C→S us|922114                       использовать лестницу (objectId)
S→C ue||922114|                     анимация объекта
S→C oe|1000                         ожидание действия, 1 с
S→C ut|3144|78|136|78|137           повернуться к лестнице
S→C do|… / ol|…                     обновление объектов вокруг
S→C uu|3144|…|78|142|1|78|136|…     новая клетка (78, 142), mapLevel = 1; lastI/lastJ — прежняя клетка
```

Спуск устроен так же: `us` на лестнице, затем `uu` с меньшим `mapLevel`. Новая клетка не совпадает с клеткой лестницы, это точка выхода на другом этаже.

**Отрисовка**

- Всё, что стоит на этаже L, сдвигается вверх на `85 · L` px (`WorldItem.cMapLevelHeight`): существа (`PlayerItem.doAction432`, `PlayerItem.processState`), объекты, эффекты гранат. Клик клиент пересчитывает обратно с учётом этажа своего персонажа ([координаты](movement.md#координаты)).
- Глубина (`World.sortView`, `ObjectItem.isPlayerNear`, `PlayerItem.isPlayerNear`): объекты и существа на этаже выше рисуются поверх существа, на этаже ниже — под ним. Объекты без прямоугольника (`rectW = −1`, перекрытия и полы) на этаже существа или ниже всегда лежат под ним. Порядок внутри одного этажа считается по клеткам и `rect`.
- **Срез верхних этажей** (`World.sortView`). Клиент ищет объекты без прямоугольника, которые стоят выше своего персонажа и чья область `hide` его накрывает. Самый нижний из них задаёт отсечку. Всё, что попадает в `bg`-области таких объектов и стоит на этаже отсечки или выше, скрывается, включая чужих персонажей. Поэтому крыша и верхние этажи здания исчезают, когда персонаж заходит внутрь. Объекты между этажом персонажа и отсечкой с флагом декораций `hide` становятся прозрачными.
- Без отсечки прозрачными становятся только объекты на этаже персонажа, чья область `hide` его накрывает.

**Взаимодействие**

- Интерактивный объект (`type != 0`) подсвечивается и кликается, только если он на этаже своего персонажа. Исключение — лестница: её можно использовать и с этажа на один выше (`ObjectItem.process`), а клетку под курсором клиент проверяет по `bg`-прямоугольнику лестницы.
- Стрелка квестовой цели (`World.updateStairsSprite`) показывает значок «вверх» или «вниз», если `level` цели из `hn`/`lp` не совпадает с этажом персонажа.

**Фон `ub`**

`ub` отличается от `sb` только способом отрисовки (`World.createBackground`, первый аргумент `true`):

- тайлы рисуются в отдельный слой `upSprite`, поднятый на один этаж (`y = −85`); после каждого `ol` клиент переставляет этот слой в списке отображения к последнему добавленному объекту (`World.setUpSprite`);
- заливка под картой почти чёрная (`#201D16`), а не песочная (`#8B8274`).

`World.createBackground` при каждом вызове очищает графику обоих слоёв, затем рисует тайлы в выбранный слой. В проверенных дампах все 45 пакетов `ub` относились к стартовой локации 252×180, где существа стоят на `mapLevel = 0`. Для основной карты 4000×4000 в этих записях приходил `sb`, а полы, перекрытия и крыши передавались как объекты `ol` со своим `mapLevel`.

Mapper сохраняет тайлы основной карты 4000×4000. Он умеет записывать `ub` в `tiles.layer = 1`, но пакеты стартовой локации отсекает по размеру карты (`tracker.setMap` в `dumper/cmd/mapper`). Поэтому пустой слой `1` совместим с наличием многоэтажных объектов в собранной карте.

## Фон `sb`/`ub`

`w × h` клеток начиная с `(i0, j0)`. Тайлы идут с шагом 4 клетки. Каждый тайл — 2 символа, 12-битный номер изображения `IMAGE_<n>` из ресурс-пака `resPack`:

```
d(c) = c - 85   если c >= 'a'
       c - 27   если c >= 'A'
       c - 48   иначе ('0'…'9', ':', ';' …)
n = d(s[k]) << 6 | d(s[k+1])
```

Порядок: внешний цикл по `i` (шаг 4), внутренний по `j` (шаг 4).

## Область видимости

Измерено по двум дампам главной карты (около 76 тыс. объектов и 1000 существ):

- Фон приходит блоками `sb` 144×144 клетки, выровненными по сетке 48 клеток. Новый блок приходит, когда персонаж подходит к краю известной области. Вокруг персонажа фон известен не меньше чем на ±48 клеток, обычно на 60–80.
- Объекты (`ol`/`do`) и существа (`ul`/`du`) сервер держит в квадрате по `i` и `j`, то есть по расстоянию Чебышёва, а не по экрану. Они появляются на расстоянии 48–56 клеток, медиана 52. Удаляются на 44–48, медиана 46. Значит, всё в пределах примерно ±46 клеток от персонажа клиенту известно.
- Сервер не помнит, что уже отправлял клиенту, и гистерезиса у него нет. В эксперименте персонаж ходил туда-обратно в пределах ±14 клеток. Сервер прислал 18 блоков `sb`, из них различных 3: блок отправляется заново при каждом пересечении линий сетки 48 (здесь `i = 864` и `j = 1584`). Записей объектов в `ol` пришло 1813 на 503 различных объекта (один объект до 13 раз), записей `do` — 1490.

## Запись объекта в `ol`

Разбор — `GameSocket.handleData`, ветка `ol`:

```
state|objectId|mapLevel|depth|type|i|j|
rectY|rectX|rectH|rectW|hideY|hideX|hideH|hideW|
<хвост>
```

Хвост зависит от типа:

- `type == 12` (звуковой объект): `soundId|p2|p3` — запись из 18 полей.
- `rectW == -1` или `type != 0`: `bgDI|bgDJ|bgH|bgW|decoCount` — смещение и размер прямоугольника фона, затем декорации.
- иначе: `decoCount`, затем декорации.

Декорации, `decoCount` штук:

- рекламный щит: `6|x|y|str1|str2` (`WorldObject.HIDE_ADVERTIZE = 6`);
- иначе: `hide|x|y|packageId|libraryId|animCount|animString` (7 полей).

Типы объектов (`game/ObjectItem.as`): 0 — декорация, 1 — ящик, 2 — дверь, 3 — лестница ([этажи](#этажи)), 5 — дверь-«ребро», 10 — объект с диалогом, 11 — депозитарий, 12 — звук, 14 — ресурс, 15 — фабрика, 16 — клановый склад продукции; 4, 6–9, 13, 17–21 — прочие.

Пример (декорация с 5 картинками):

```
ol|0|215922|0|195912|0|512|28|0|-4|3|3|-12|-2|14|14|5|0|-75|-54|68|37|0||1|-41|-130|68|41|0||…
```
