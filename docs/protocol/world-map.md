Сводная таблица команд `sb`, `ub`, `ol`, `do` и др. — в [server-commands.md](server-commands.md#мир-карта-и-объекты).

## Этажи

Все этажи многоуровневой локации лежат в одной сетке `i`, `j`. Поле `mapLevel` задаёт этаж, где `0` — уровень земли. На основной карте, например, объекты могут занимать этажи 0–4, а существа встречаться на этажах 0, 1 и 3.

**Где передаётся этаж**

| Сообщение | Поле | Примечание |
|---|---|---|
| `ol` | `mapLevel` (поле 3 записи объекта) | у каждого объекта карты |
| `ul`, `uu` | `mapLevel` после `i`, `j` ([записи игроков](data-structures.md#записи-игроков)) | только в полных записях существ |
| `fb` | `mapLevel`, `blowLevel` | этаж броска и этаж взрыва: граната может лететь между этажами |
| `lp`, `hn` | `level` | этаж цели квеста |

В `mv`, `md` и `ms` этажа нет. Обычная ходьба всегда идёт в пределах одного этажа, клиент оставляет текущий `mapLevel` существа.

**Переход между этажами**

Лестница — объект `ol` с `type = 3`. Клиент использует её командой `us`, а сервер перемещает персонажа в клетку на другом этаже. Ниже показан пример подъёма.

```
C→S us|922114                       использовать лестницу (objectId)
S→C ue||922114|                     анимация объекта
S→C oe|1000                         ожидание действия, 1 с
S→C ut|3144|78|136|78|137           повернуться к лестнице
S→C do|… / ol|…                     обновление объектов вокруг
S→C uu|3144|…|78|142|1|78|136|…     новая клетка (78, 142), mapLevel = 1; lastI/lastJ — прежняя клетка
```

Спуск устроен так же: `us` на лестнице, затем `uu` с меньшим `mapLevel`. Новая клетка не совпадает с клеткой лестницы, это точка выхода на другом этаже.

**Отрисовка**

- Существа, объекты и эффекты на этаже `L` рисуются на `85 · L` пикселей выше уровня земли. При клике по карте клиент пересчитывает координаты с учётом этажа своего персонажа. См. [координаты](movement.md#координаты).
- Клиент рисует объекты и существ с верхних этажей поверх нижних. Объекты без прямоугольника (`rectW = −1`, например перекрытия и полы) на этаже существа или ниже лежат под ним. Порядок внутри одного этажа определяется по клеткам и прямоугольникам `rect`.
- **Срез верхних этажей.** Клиент ищет объекты без прямоугольника, которые стоят выше своего персонажа и чья область `hide` его накрывает. Самый нижний из них задаёт отсечку. Всё, что попадает в `bg`-области таких объектов и стоит на этаже отсечки или выше, скрывается, включая чужих персонажей. Поэтому крыша и верхние этажи здания исчезают, когда персонаж заходит внутрь. Объекты между этажом персонажа и отсечкой с флагом декораций `hide` становятся прозрачными.
- Без отсечки прозрачными становятся только объекты на этаже персонажа, чья область `hide` его накрывает.

**Взаимодействие**

- Интерактивный объект (`type != 0`) подсвечивается и доступен для клика с этажа своего персонажа. Лестницу можно использовать также с этажа на один выше. Клиент проверяет попадание курсора по её прямоугольнику `bg`.
- Клиент показывает стрелку квестовой цели вверх или вниз, если `level` из `hn` или `lp` отличается от этажа персонажа.

**Фон `ub`**

`ub` использует формат `sb` и меняет отрисовку фона.

- Клиент рисует тайлы `ub` на 85 пикселей выше слоя `sb`. После каждого `ol` слой `ub` перемещается в порядке отрисовки к последнему добавленному объекту.
- Цвет заливки под картой для `ub` — `#201D16`, для `sb` — `#8B8274`.

При получении `sb` или `ub` клиент очищает оба слоя и заново рисует фон в соответствующем слое. Например, стартовая локация 252×180 использует `ub`, а существа в ней находятся на `mapLevel = 0`. На основной карте 4000×4000 фон передаётся через `sb`, а полы, перекрытия и крыши — как объекты `ol` со своим `mapLevel`.

## Фон `sb`/`ub`

`w × h` клеток начиная с `(i0, j0)`. Тайлы идут с шагом 4 клетки. Два символа каждого тайла кодируют 12-битный номер изображения из набора `resPack`.

```
d(c) = c - 85   если c >= 'a'
       c - 27   если c >= 'A'
       c - 48   иначе ('0'…'9', ':', ';' …)
n = d(s[k]) << 6 | d(s[k+1])
```

Для каждого `i` сначала идут все тайлы по возрастанию `j`. Затем `i` увеличивается на 4, и `j` снова начинается с `j0`.

## Область видимости

Ниже приведены типичные размеры и расстояния для основной карты.

- Фон приходит блоками `sb` 144×144 клетки, выровненными по сетке 48 клеток. Новый блок приходит, когда персонаж подходит к краю известной области. Вокруг персонажа фон известен не меньше чем на ±48 клеток, обычно на 60–80.
- Объекты (`ol`/`do`) и существа (`ul`/`du`) сервер держит в квадрате по `i` и `j`, то есть по расстоянию Чебышёва, а не по экрану. Они появляются на расстоянии 48–56 клеток, медиана 52. Удаляются на 44–48, медиана 46. Значит, всё в пределах примерно ±46 клеток от персонажа клиенту известно.
- При пересечении линий сетки с шагом 48 сервер может повторно прислать уже известный клиенту блок `sb`. Например, при движении туда и обратно в пределах ±14 клеток сервер отправил 18 блоков `sb` для трёх разных областей. Обновления объектов `ol` и `do` также могут повторяться.

## Запись объекта в `ol`

```
state|objectId|mapLevel|depth|type|i|j|
rectY|rectX|rectH|rectW|hideY|hideX|hideH|hideW|
<хвост>
```

Хвост зависит от типа:

- `type == 12` (звуковой объект): `soundId|p2|p3` — запись из 18 полей.
- `rectW == -1` или `type != 0`: `bgDI|bgDJ|bgH|bgW|decoCount` — смещение и размер прямоугольника фона, затем декорации.
- иначе: `decoCount`, затем декорации.

Декорации, `decoCount` штук:

- рекламный щит имеет формат `6|x|y|str1|str2`;
- иначе: `hide|x|y|packageId|libraryId|animCount|animString` (7 полей).

Типы объектов — `0` для декораций, `1` для ящиков, `2` для дверей, `3` для [лестниц](#этажи), `5` для дверей-«рёбер», `10` для объектов с диалогом, `11` для депозитариев, `12` для звуков, `14` для ресурсов, `15` для фабрик, `16` для клановых складов продукции. Типы `4`, `6`–`9`, `13` и `17`–`21` относятся к прочим объектам.

Пример (декорация с 5 картинками):

```
ol|0|215922|0|195912|0|512|28|0|-4|3|3|-12|-2|14|14|5|0|-75|-54|68|37|0||1|-41|-130|68|41|0||…
```
